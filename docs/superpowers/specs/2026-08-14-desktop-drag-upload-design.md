# 收集箱与文件库桌面拖拽上传设计

## 目标

让用户可以直接从 Windows 桌面或文件资源管理器，把文件或整个文件夹拖入个人工作台，不再先点“上传”再选择文件。

本次只优化本地原型的导入体验，不接入云上传、同步队列和断点续传。

## 统一交互

- 当外部文件进入页面时，显示整页半透明拖拽蒙层和明确的放置目标。
- 只有来自操作系统的文件拖拽才触发蒙层；知识库、文件库内部的排序和移动不触发。
- 使用拖拽进入层级计数避免蒙层在经过子元素时闪烁。
- 支持一次拖入多个文件，也支持拖入整个文件夹。
- 上传按钮继续保留，作为不方便拖拽时的备用入口。
- 导入后显示汇总反馈：成功数量、跳过数量及主要原因。

## 收集箱

- 文件拖到收集箱页面任意位置即可收集。
- 拖入文件夹时，递归读取其中的文件，每个文件生成一条收集箱记录。
- 收集箱不创建目录树，但记录文件原始相对路径，方便用户识别来源。
- 图片仍识别为图片类型，其他内容识别为文件类型。
- 单个文件超过原型限制时只跳过该文件，不影响同批其他文件。

## 文件库

- 拖到文件内容区：导入到当前打开的文件夹。
- 拖到左侧某个文件夹：导入到该指定文件夹，并高亮目标。
- 拖入整个文件夹时，自动创建对应目录并完整保留多级层级。
- 同目录出现重名时自动生成 `名称 (1)`、`名称 (2)`，不覆盖已有内容。
- 文件库内部拖动仍用于移动条目，与外部文件上传分开判断。

## 文件夹读取与兼容

- Chromium/Tauri 环境优先使用拖拽条目的目录读取能力递归遍历文件夹。
- 目录读取需要持续读取分批结果，直到为空，避免大型目录只导入第一批文件。
- 浏览器不支持目录拖拽接口时，退化为导入浏览器能够提供的普通文件，并提示未能保留目录层级。
- 单次最多处理 1000 个文件和目录条目，达到上限后停止继续读取并提示，避免页面卡死。

## 原型限制与错误处理

- 延续当前单文件 20 MB 的本地测试限制。
- 每个文件单独校验；某个文件失败不能让整批失败。
- 空文件夹允许在文件库中创建；收集箱中不单独生成空文件夹记录。
- 读取失败、文件超限和条目超限都汇总展示，不连续弹出多个提示框。
- 当前使用 IndexedDB 保存文件 Blob，刷新页面后记录仍存在；这不是云端上传。

## 状态与反馈

- 拖拽中：显示“松开后上传到当前文件夹 / 指定文件夹 / 收集箱”。
- 处理中：显示已处理条目数量；本地原型不伪装网络上传百分比。
- 完成后：显示简短结果，例如“已导入 18 个文件，跳过 2 个超限文件”。
- 文件库导入完成后保持在当前目录，并立即显示新增内容。

## 验收标准

1. 从桌面拖入单个文件到收集箱，松开后生成对应记录。
2. 同时拖入多个文件，其中一个超过 20 MB，其余文件仍能成功导入。
3. 拖入含两级子目录的文件夹到文件库，页面生成相同目录层级。
4. 拖到文件库左侧指定文件夹后，内容进入该文件夹而不是当前目录。
5. 同名文件不会覆盖，自动添加序号。
6. 页面内移动文件或知识条目时不出现外部上传蒙层。
7. 拖拽离开页面或按 Esc 后蒙层消失。
8. 刷新页面后已导入的文件和收集箱记录仍存在。

## 暂不包含

- 云对象存储上传
- 上传速度和剩余时间
- 断点续传
- 自动同步 Windows 文件夹
- 文件冲突内容比较
