# 知识库第一阶段设计

## 目标与边界

在现有个人工作台中交付一个本地可用的知识库原型，提供多级目录、富文本编辑、自动保存和本地搜索。第一阶段使用 Tiptap 3 与 IndexedDB，不接后端、PostgreSQL、AI、多人协作、权限、评论、公开分享、版本历史、知识图谱或实时协同。

## 技术选择

- 编辑器采用 Tiptap 3，内容保存为结构化 JSON。
- 目录拖拽继续使用 dnd-kit。
- 文档、目录、图片及搜索文本保存在 IndexedDB。
- UI 通过统一数据适配器读写，不直接访问 IndexedDB，以便后续替换为 API 和 PostgreSQL。
- 不整体引入 Novel 或 BlockNote，避免带入 AI、云存储和强绑定的默认交互。

## 页面结构

知识库沿用工作台固定主导航。右侧顶部工具栏包含页面标题、文档搜索、新建文档和新建文件夹。下方采用两栏布局：左侧约 260 像素宽的目录树，右侧为文档标题和正文编辑区。

窄屏时目录树可以收起，编辑器保持完整宽度。页面不增加统计卡片、推荐内容或 AI 入口。

## 目录树

文件夹和文档使用统一树结构，支持任意层级：

- 展开与收起。
- 新建文档和文件夹。
- 行内重命名。
- 同级排序。
- 拖动到其他文件夹。
- 删除到知识库回收站。
- 从回收站恢复或永久删除。

禁止把文件夹移动到自身或自己的后代。文档和文件夹名称在同一父目录内不能重复。

## 文档编辑

文档标题独立于正文。正文支持：

- 一级、二级、三级标题。
- 正文、加粗、斜体、下划线和删除线。
- 无序列表、有序列表和任务列表。
- 引用、代码块、分割线和链接。
- 图片和表格。
- 撤销与重做。

编辑交互保持轻量：选中文字显示浮动格式工具栏，输入 `/` 显示插入菜单。第一阶段的斜杠菜单只包含编辑器已支持的块，不提供 AI 命令。

## 自动保存

标题或正文变化后进入“保存中”状态，停止输入约 500 毫秒后写入 IndexedDB。成功显示“已保存”，失败显示“保存失败”并保留当前内存内容，允许再次编辑触发重试。

页面切换和刷新前应提交待保存内容。文档树标题和编辑区标题共用同一数据，不能分别保存。

## 图片

支持选择文件、粘贴和拖入图片。图片 Blob 与正文 JSON 分开保存，正文只记录稳定图片 ID。第一阶段设置单图大小限制，超限时就地提示，不读取文件。

后续接入文件库时，图片节点可以引用文件库条目；第一阶段不预先实现该关联。

## 搜索

搜索范围包括未删除文档的标题与正文纯文本。结果显示文档标题、内容片段和所属目录。点击结果打开文档，并在结果片段中高亮关键词。

每次保存文档时同步生成 `plainText`，搜索时不重新解析全部 Tiptap JSON。第一阶段不做语义搜索、模糊向量检索或 AI 摘要。

## 数据模型

目录和文档共用知识节点模型：

- `id`：稳定标识。
- `parentId`：父文件夹标识，根目录为空。
- `type`：`folder` 或 `document`。
- `title`：名称或文档标题。
- `sortOrder`：同级顺序。
- `createdAt`：创建时间。
- `updatedAt`：修改时间。
- `deletedAt`：进入回收站时间。
- `originalParentId`：恢复目标。

文档额外包含：

- `contentJson`：Tiptap JSON。
- `plainText`：搜索文本。
- `lastSavedAt`：最后保存时间。

图片记录包含 `id`、`documentId`、`mimeType`、`size`、`blob` 和创建时间。

## 组件边界

- `KnowledgeBasePage`：页面状态与布局。
- `KnowledgeToolbar`：搜索、新建文档和新建文件夹。
- `KnowledgeTree`：目录、选择和拖拽。
- `DocumentEditor`：标题、Tiptap 编辑器和保存状态。
- `EditorToolbar`：选择格式工具。
- `SlashCommandMenu`：块插入菜单。
- `KnowledgeSearch`：搜索结果和跳转。
- `KnowledgeRecycleBin`：恢复和永久删除。
- `useKnowledgeBase`：查询、变更和派生数据。
- `knowledgeStore`：IndexedDB 读写和迁移。

## 错误处理

- IndexedDB 初始化失败时显示明确错误，不回退到易丢失的内存模式。
- 名称冲突、图片超限和保存失败在操作位置反馈。
- 删除先进入回收站，永久删除需要二次确认。
- 编辑器扩展或图片渲染失败不能导致整个知识库白屏。
- 打开已删除或不存在的文档时返回知识库空状态。

## 验证标准

- 可以创建至少三级文件夹并在其中创建文档。
- 文档可重命名、移动、排序、删除和恢复。
- 标题、列表、任务列表、引用、代码块、图片和表格可以插入并重新加载。
- 停止输入后自动保存，刷新后标题和正文保持一致。
- 搜索可以同时命中标题和正文，并打开正确文档。
- 目录拖动不能形成循环层级。
- 使用真实图片完成粘贴或上传验证。
- 列表空状态、无搜索结果和保存失败均有可理解反馈。
- 代码检查、类型检查和生产构建通过。
- 使用真实浏览器完成端到端交互并检查控制台错误。

## 第二阶段接口

后端阶段将 IndexedDB 适配器替换为 API 适配器，服务端使用 PostgreSQL 保存节点、文档 JSON 和搜索文本，图片存入文件库或对象存储。编辑器 JSON 和节点模型保持不变，避免重写前端编辑体验。
