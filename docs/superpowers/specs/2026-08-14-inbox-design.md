# 收集箱 MVP 设计

## 目标

收集箱是临时内容中转站。用户可以先快速保存内容，之后再转为任务、知识库文档或文件库文件，避免因为当下没有时间分类而遗漏信息。

## 收集方式

- 页面顶部提供常驻快速输入框。
- 输入文字或粘贴链接后，按 Enter 或点击“收集”保存。
- 以 `http://` 或 `https://` 开头的单一内容自动识别为链接，否则按文字保存。
- 提供“上传图片”和“上传文件”入口，并支持把本地文件拖入快速收集区。
- 第一版文件保存在浏览器本地数据存储中，单个文件限制为 20MB；超过限制时显示明确错误，不创建收集项。

## 页面结构

采用单列列表布局。

顶部筛选：

- 待整理
- 全部
- 文字
- 链接
- 图片/文件
- 已整理

每个收集项显示：

- 类型图标
- 文字摘要、链接地址、图片缩略图或文件名称
- 文件大小（附件类型）
- 收集时间
- 可用的整理操作
- 更多菜单：编辑文字或链接、删除

## 整理动作

### 转为今日任务

- 适用于文字和链接。
- 任务名称取内容第一行；链接没有附加文字时使用链接地址。
- 创建普通优先级、个人分类、无指定时间的待办任务。
- 创建成功后，原收集项标记为已整理，并记录去向为“今日任务”。

### 转为知识库文档

- 适用于文字和链接。
- 在第一个可用知识库的根目录创建文档。
- 标题取内容第一行，正文保留完整文字或链接。
- 如果还没有知识库，提示用户先创建知识库，原收集项保持待整理。
- 创建成功后标记已整理，并记录去向为“知识库”。

### 移入文件库

- 仅适用于图片和普通文件。
- 文件进入文件库根目录，保留名称、大小、类型和本地数据。
- 创建成功后标记已整理，并记录去向为“文件库”。

## 状态与删除

- 已整理内容仍保留在收集箱，可从“已整理”筛选查看。
- 支持把已整理内容恢复为待整理，不删除已创建的任务、知识文档或文件。
- 删除收集项需要二次确认，删除不会反向删除已创建到其他模块的内容。
- 左侧导航徽标显示真实待整理数量，不再显示固定数字。

## 数据与错误处理

- 收集项使用独立本地存储，不与任务、知识库和文件库数据混在同一个结构中。
- 保存失败、文件超限、缺少知识库或转移失败时显示页面内错误提示。
- 只有目标模块创建成功后才标记已整理，避免内容丢失。

## 验收标准

- 可以快速收集文字、链接、图片和普通文件，刷新页面后内容仍存在。
- 筛选数量和列表内容一致。
- 文字或链接可以转为今日任务和知识库文档。
- 图片或文件可以移入文件库。
- 整理成功和失败的状态明确，失败时不会错误隐藏原内容。
- 左侧收集箱徽标显示真实待整理数量。
- 通过 ESLint、TypeScript 生产构建和实际浏览器交互验证。
